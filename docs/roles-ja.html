四つの役割

goals が目標と範囲を切り出し、planner だけが次の一手を出し、worker は一つ実行して止まり、mainagent は人の窓口になる。下の図は、プロンプトがどう積まれ、処理がどこで止まるかを辿る。

役割ごとの中身

左がプロンプトの義務、右がエンジン側の処理。ツール名は呼び出し口であり、手順そのものではない。

01 · 一度

goals

探索ループには入らない。セッションは exp{id}-goals。

プロンプト

  1. 書いてある操作の境界を set_constraints へ。指示語は具体的なホストやポートに置き換える。無ければ呼ばない。
  2. 明示された範囲だけを add_task_scope へ。ホスト名は完全なサブドメイン。裸のルートか「全体」とあるときだけルートドメイン。
  3. 検証できる最終結果だけを set_goals へ。偵察や手順は子目標にしない。

処理

  1. タスク開始時に一度。最大 8 ターン。権限は bypass。
  2. ツールは制約、範囲、目標の三つまで。範囲ツールは資産ストアとタスク ID があるときだけ付く。
  3. 目標ノードはツールが探索グラフへ直接書く。何も残らなければ、目標の原文を一つ残す。
  4. 活動ログ上の名前は画面用に planner と付く。
ツール set_constraints add_task_scope set_goals
02 · 起きるたび

planner

次の intent を出す人はここだけ。セッションは exp{id}-planner。

プロンプト

  1. ユーザーメッセージに、発火理由とグラフの要約 JSON が入っている。システム側は役割の本文だけ。
  2. 証拠が揃った goal を prove_goal。数値条件は実測と照合し、未達なら intent を足す。
  3. open / running と重複するものは出さない。完了済みは、新しい材料が無い限り再発行しない。途中で切れたものはトレースを見て継続か再発行かを選ぶ。
  4. 依存する段は一歩だけ。独立した方向は並べてよい。出すときは add_intent を一度、最大 4 件。
  5. 未達で待ちも走行も無いときは、少なくとも 1 件。終局ラウンドは判定だけで、新しい intent は出さない。

処理

  1. グラフの変化をまとめてから、または心拍で Plan。
  2. 一時停止、削除、完了、収拾中、目標が無い状態では LLM を呼ばない。目標が無く待ち行列も空なら done。
  3. Todo は探索 ID で目覚めをまたいで残る。このチャットの外にある。
  4. 全 goal が met になると、走行中の worker を止め、タスクを done にする。
  5. Bash と WebFetch は記録プロキシ経由。Web 検索は既定でオフ。
主なツール graph_overview list_facts list_findings node_detail list_assets list_untested_assets add_intent prove_goal steer_work kill_work get_worker_trace
03 · 並列

worker

intent を一つ claim し、書いて、止まる。プールの数だけ同時に走る。

プロンプト

  1. 領分は受け取った一文だけ。別方向の手がかりは事実の要約に一行残し、自分では追わない。
  2. 資産そのものは insert_assets。観察は record_fact。今回再現できたものだけ report_finding。
  3. 操作制約は、intent より上。反するコマンドは出さない。
  4. intent 本文と対象資産はシステムプロンプトに置き、圧縮で落ちないようにする。全体状況はユーザー側の読み取り専用。

処理

  1. frontier から一つ取り、Execute。作業場所はその intent 専用。
  2. すべてのツール呼び出しは Guard を通る。補正文は次のツールの前に入る。
  3. 検出を書いた瞬間に planner を起こす。終了を待たない。
  4. 終わりは、自ら止まる、歩数、時間、kill、一時停止、目標達成。上限時は書き残しだけを収拾する。
  5. 同じ intent の再実行は会話の続きから。モデルエラーだけ、エンジンが回数を決めてやり直す。
主なツール Bash WebFetch record_fact report_finding insert_assets list_assets list_findings node_detail traffic_search
04 · 人が話すたび

mainagent

自律ループは持たない。セッションは exp{id}-main。

プロンプト

  1. 進捗はグラフと worker 出力を読んで答える。ツールの戻り以外は言わない。
  2. 方向の変更は add_hint。今すぐ試す対象は高優先の add_intent。
  3. 走行中の補正は steer_work。目標の追加は set_goals。境界の変更は set_constraints。
  4. すでに全目標が met で、新しい intent が新しい最終結果に見えるときは、登録するか人に確認する。

処理

  1. 人のメッセージごとにセッションを作り、同じ会話記録を読み戻してから答える。
  2. ヒントと新しい目標は planner を起こす。目標追加は、完了や一時停止のタスクを running に戻す。
  3. steer_work は走行中 worker の次のツール前に入る。kill_work と prove_goal は planner 側。
  4. このチャットの Todo はターンが終わると捨てる。歩数上限では進捗を一文で終える。
主なツール graph_overview list_findings list_facts get_worker_output add_hint add_intent steer_work set_goals set_constraints

二つのグラフ

探索グラフ

goal、intent、fact、finding、hint。タスクごとに分かれる。planner が読み、worker が fact と finding を足す。

資産グラフ

ドメイン、ホスト、IP、サービス、エンドポイント。タスク間で共有する。worker の insert_assets のあと、DNS と HTTP の補完が非同期で走る。

範囲

goals が登録した task scope が、そのタスクの分母になる。planner は未測の資産を見て、足りない方向だけ intent にする。

止まる場所

人が手を出す経路は三つある。承認ダイアログは mainagent の中にはない。

intercept

ルールが ask のとき、そのツール呼び出しを保留する。人は許可または拒否する。deny はその場で戻る。worker の実行フックに付く。

mainagent

チャットで方針を変える。ヒント、intent、目標、制約、走行中の補正。ツールの実行そのものは止めない。

planner の停止

kill_work は一つの work だけ止める。全 goal の達成、一時停止、削除、時間切れは、エンジンが走行中の実行を打ち切る。

このページは制御の流れです。役割のプロンプト本文（攻撃の進め方）は載せていません。本文は agent/goals.go、planner.go、worker.go、mainagent.go にあり、実行時は agent/prompt.go の renderSystem が組み立てます。
